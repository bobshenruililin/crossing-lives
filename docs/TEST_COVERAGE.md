# What verification is intended to prove

Test counts are evidence of coverage, not a measure of whether the place is engaging. The release gate combines exact-commit browser execution, actual viewport captures and a recorded interaction reviewed by a person.

## Preserved calculation and ownership checks

The domain tests retain exact amounts, native currencies, group/per-person scope, return timing, closing margins, unknowns and fixed-pool conservation. Story tests retain guarded commitments, once-only delays, immutable previous attempts and safe decoding. A direct return after dinner is an explicit zero-walk action, derived through the same domain engine; being late remains late.

Browser cases verify the real choices, clock and bill in both cities. Rounded choice summaries are explicitly labelled “about”; exact-cent figures remain in the Wallet and engine assertions. Scene media must actually decode, and the portable file must complete both city paths with network offline.

## Intentional interaction changes

- Initial entry is now the illustrated world, so a marketing-header/cover assertion would test an obsolete requirement.
- Memento and note-entry tasks were removed. Compatibility tests seed authored legacy records and prove preservation instead of recreating unwanted collection prompts.
- Jun and choices appear during conversation. His portrait must decode when that conversation is open; permanent portrait visibility is no longer required.
- Wallet and phone details are opened through their real controls rather than expected in a permanent dashboard.
- A phone-sized world can pan. Tests verify the actual image/hotspot coordinate relationship, named-control reachability and unobstructed targets rather than requiring the entire landscape in one narrow frame.

## Guarding against misleading passes

- Initial-invitation screenshots and assertions happen before a helper can dismiss dialogue. Exploration screenshots are named separately.
- The artwork’s visible area is measured, not just a full-height empty wrapper. Portrait tablets are included alongside phones and desktop.
- Keyboard-only activation uses Tab, Enter and Space. Modal traversal is checked forward and backward; Escape and focus return remain required.
- Reduced-motion checks observe computed animations, transitions and scroll behavior, not just the requested media preference.
- At least one deadline scenario uses the actual setup preset and delay checkbox. Seeded states remain useful for compatibility and edge cases, but do not replace those control checks.
- Free observations are checked after dinner, after a walk and at home so future-tense copy cannot silently contradict commitments.
- Reconsidering an evening asks for confirmation only when it would destroy an older hidden note/detail. Cancel and Escape preserve serialized state; confirmation applies the existing guarded action.
- A test locator ambiguity is corrected by targeting the actual element, while retaining its warning text and data assertions. Assertions are not weakened to accept a genuine focus or layout failure.

## Human review

Inspect what is actually attended to, how a decision changes the place, whether the next action is understandable, and whether dialogue obscures its subject. Watch the real opening rather than inferring pacing from screenshots. A scene can satisfy dimensions yet still feel static or overloaded; that remains a design defect to address.


## Route-note and monetary-layout increment

The map's full-evening forecast intentionally differs from the earlier incomplete phone prediction: it now includes the future disclosed dinner delay by composing the same guarded story previews used by meal choices. Tests must assert the actual unchanged clock during inspection, the stated assumptions, rail/road consequences, full outward and return legs, and the committed-route restriction. A new prediction is not accepted merely because its text changed.

The Wallet test measures rendered text-line boxes, clipping and readable font size, alongside exact amounts. A no-overflow check of the page would not catch a final digit wrapping within its own cell. Phone-sized source and route folds need real screenshots and focus behavior checks as well as DOM assertions.
